    How kubeconfig Is Generated by Kubespray and k3d¶

    kubeconfig files tell kubectl (and other clients) how to reach a cluster and how to authenticate. By default, kubectl looks for a file named config in ~/.kube/, but tools like Kubesprayandk3d generate and manage additional kubeconfigs for the clusters they create.123

    Common kubeconfig concepts¶

    A kubeconfig file is a YAML document containing:

    • clusters — API server endpoints and TLS settings.
    • users — credentials (client certificates, tokens, etc.).
    • contexts — a tuple of (cluster, user, namespace) to make a "profile".

    kubectl chooses which cluster to talk to based on the current context. You can point it to a specific file by:

    • Setting KUBECONFIG=/path/to/kubeconfig, or
    • Using kubectl --kubeconfig=/path/to/kubeconfig ...4251

    Tip

    You can merge multiple kubeconfig files by setting KUBECONFIG to a colon-separated list of paths, e.g. export KUBECONFIG=~/.kube/config:~/kubeconfigs/admin.conf

    Kubespray: kubeconfig generation flow¶

    Kubespray is an Ansible playbook collection that installs a production-grade Kubernetes cluster on your own hosts. As part of the control-plane bootstrap, it generates kubeconfig files on the master/control-plane nodes and optionally on worker nodes.678

    Where kubeconfig lives with Kubespray¶

    On each control-plane node, Kubespray (via kubeadm) creates:

    File Purpose
    /etc/kubernetes/admin.conf Admin kubeconfig (cluster-admin privileges)
    /etc/kubernetes/kubelet.conf Kubelet client config
    /etc/kubernetes/controller-manager.conf Controller manager config
    /etc/kubernetes/scheduler.conf Scheduler config

    Localhost-bound by default

    Kubespray kubeconfigs generally point to localhost on control-plane nodes, or to a local nginx proxy / external load balancer if configured.86

    "The kubeconfig files generated will point to localhost (on kube_control_planes) and kube_node hosts will connect either to a localhost nginx proxy or to a loadbalancer if configured."6

    Practically:

    • Control-plane nodes talk to the API server via https://127.0.0.1:6443.
    • Worker nodes may point at a local nginx proxy or a dedicated external load balancer.86

    How Kubespray generates kubeconfig¶

    1. kubeadm init on the first control-plane node

    kubeadm generates a CA and server/client certificates, then writes admin.conf and other component configs under /etc/kubernetes/.98

    1. Ansible templates and copies kubeconfig

    Kubespray's Ansible roles read admin.conf and adjust the server: field to point to either https://127.0.0.1:6443 or an HA load balancer.68

    1. Expose kubeconfig to the operator machine (manual step)

    Copy the file from the control-plane node to your workstation: [code] scp ubuntu@cp-1:/etc/kubernetes/admin.conf ~/kubeconfigs/admin.conf export KUBECONFIG=~/kubeconfigs/admin.conf kubectl get nodes

    [/code]

    Or merge it into ~/.kube/config using kubectl config commands.24

    1. Using kubeconfig on the control-plane node directly

    SSH to a control-plane node and run: [code] export KUBECONFIG=/etc/kubernetes/admin.conf kubectl get nodes

    [/code]

    This talks to the API server bound to 127.0.0.1:6443 on that host.86

    Key characteristics of Kubespray kubeconfig¶

    • Source of truth is admin.conf produced by kubeadm on the first control-plane node.98
    • Transport is https with client certs (cluster-admin credentials).
    • Endpoints are typically localhost or a configured load balancer.68
    • Distribution to operators is a manual step — Kubespray does not write kubeconfig on your laptop.

    k3d: kubeconfig generation flow¶

    k3d runs k3s (a lightweight Kubernetes distribution) inside Docker containers. Unlike Kubespray, it has direct control over both the control-plane and the CLI environment, so it can generate and update kubeconfigs on the fly.1011

    Where kubeconfig lives with k3d¶

    By default, k3d integrates with your existing kubeconfig:

    • It detects the "default" kubeconfig as the file pointed to by KUBECONFIG (if it references exactly one file), or ~/.kube/config if KUBECONFIG is unset.1110

    k3d can also:

    • Write a cluster-specific kubeconfig to ~/.k3d/kubeconfig-<cluster-name>.yaml.11
    • Merge cluster details into your default kubeconfig and optionally switch context.

    How k3d generates kubeconfig during cluster creation¶

    When you run k3d cluster create mycluster, the steps are:

    1. k3s server inside Docker creates its own kubeconfig

    k3s writes /etc/rancher/k3s/k3s.yaml inside the container, containing the API endpoint and certs.12

    1. k3d reads and adapts that kubeconfig

    k3d inspects the container, reads the internal kubeconfig, and rewrites the server: URL to a host-accessible endpoint (e.g., https://0.0.0.0:<mapped-port>).11

    1. k3d writes or merges kubeconfig on the host

    By default (k3d v5.x+), --kubeconfig-update-default is enabled:11

     * Merges the new cluster into `~/.kube/config` (or `$KUBECONFIG`).
 * Does **not** switch context unless you also pass `--kubeconfig-switch-context`.

    [code] kubectl config get-contexts # shows k3d-mycluster

    [/code]

    k3d kubeconfig commands¶

    Write standalone Print to stdout Merge into file 

        k3d kubeconfig write mycluster
    # creates ~/.k3d/kubeconfig-mycluster.yaml

        k3d kubeconfig get mycluster > ./kubeconfig-mycluster.yaml
    export KUBECONFIG=./kubeconfig-mycluster.yaml
    kubectl get nodes

        k3d kubeconfig merge mycluster --output some/other/file.yaml
    # or into default kubeconfig:
    k3d kubeconfig merge mycluster --kubeconfig-merge-default

    Switching context

    Add --kubeconfig-switch-context to any merge/write command to make the new cluster the active context.1011

    Example flows with k3d¶

    Default — merge into ~/.kube/config 

        k3d cluster create mycluster
    kubectl config get-contexts
    kubectl config use-context k3d-mycluster
    kubectl get nodes

    k3d pulls the kubeconfig from k3s inside Docker, merges it into your default kubeconfig, and leaves the current context unchanged unless --kubeconfig-switch-context is used.11

    Standalone kubeconfig only 

        k3d cluster create mycluster --kubeconfig-update-default=false
    k3d kubeconfig write mycluster
    export KUBECONFIG=~/.k3d/kubeconfig-mycluster.yaml
    kubectl get nodes

    Useful for isolating cluster configs in scripts or demos.1011

    Key characteristics of k3d kubeconfig¶

    • Automatic — k3d always has a kubeconfig per cluster; merge or write standalone.11
    • Context management — optionally switch context via --kubeconfig-switch-context.1011
    • Host-visible endpoint — rewrites the server: URL from the k3s internal address to a host-reachable address/port.

    Summary: Kubespray vs k3d¶

    Aspect Kubespray k3d
    Primary environment Bare-metal/VM hosts k3s inside Docker (local/dev)
    Where kubeconfig is created /etc/kubernetes/admin.conf via kubeadm Inside k3s container, exported to host
    Default endpoint https://127.0.0.1:6443 or nginx/LB Host-reachable mapped Docker port
    How operator gets kubeconfig :material-hand-right: Manual copy from node Auto-merged into default kubeconfig
    Integration with ~/.kube/config Not automatic Automatic (unless disabled)
    Context switching Manual via kubectl config use-context Optional via --kubeconfig-switch-context

    Both tools produce standard kubeconfig files — the main differences are wherethey originate andhow much automation they provide for placing and merging them.611

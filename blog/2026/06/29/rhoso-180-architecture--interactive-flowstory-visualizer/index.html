    RHOSO 18.0 Architecture — Interactive FlowStory Visualizer¶

    An interactive, animated architecture diagram for Red Hat OpenStack Services on OpenShift (RHOSO) 18.0, built with FlowStory. A single self-contained HTML file that visualizes 96 operational flows with 1476 animated steps across 26 categories — covering the podified control plane, EDPM data plane, Rook-Ceph storage, GitOps/CI-CD, NFV/telco, AI/ML, Red Hat IDM, spine-leaf networking, and disaster recovery.

    What Is This?¶

    RHOSO 18.0 runs the OpenStack control plane as Kubernetes-native pods on Red Hat OpenShift, while managing bare-metal compute nodes via the External Data Plane Management (EDPM) pattern. Understanding how requests traverse these boundaries — from API call to VM boot to OVN packet path — is non-trivial.

    This visualizer makes it concrete. Each flow animates step-by-step through the real components, showing API payloads in the inspector panel and letting you click any node for a detailed tooltip.

    How It Was Built¶

    The visualizer is a single flow.html file using the FlowStory framework:

    • CSS loaded from noyitz.github.io/flowstory/templates/style.css
    • JS engine loaded from noyitz.github.io/flowstory/src/index.js
    • Diagram JSON embedded inline — nodes, tooltips, flows, and inspector mutations are all in one const diagram = {...} object
    • Auto-play with loop mode enabled on page load

    The JSON schema declares:

    • Nodes with x, y, w, h coordinates, grouped inside boundary and container parent nodes
    • Tooltips keyed by node ID, with title, description, detail key-value pairs, and external links
    • Flows as ordered step arrays using arrow (animated edge) and lightup (node highlight) modes
    • Inspector mutations that update the right-panel request/response display at each step

    Self-Contained

    The entire diagram — 78 component tooltips, 96 flows with 1476 steps across 26 categories, and full inspector mutations — lives in a single ~1MB HTML file with zero build tooling required. Just open it in a browser.

    Key Highlights¶

    Redfish BMC + Ironic Flow¶

    The newest flow (Flow 13) shows the complete bare-metal onboarding path:

    1. Admin applies a BareMetalHost CR with a Redfish BMC address
    2. BMO (Bare Metal Operator) registers the node with Ironic
    3. Ironic Conductor calls Redfish REST endpoints on the BMC: GET /Systems/1, InsertMedia, Reset
    4. IPA (Ironic Python Agent) ramdisk boots, inspects hardware, reports inventory
    5. Ironic provisions RHEL 9 via IPA, reboots to HDD
    6. EDPM Ansible installs nova-compute, ovn-controller, libvirt
    7. Node registers with the control plane and starts accepting workloads

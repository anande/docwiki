    Secure ArgoCD JWT Tokens for Cursor MCP¶

    When using the ArgoCD MCP server in Cursor, the default configuration stores the API token as plaintext in ~/.cursor/mcp.json. This guide covers multiple approaches to secure the token properly.

    The Problem¶

    A typical mcp.json config exposes the token in plain sight:

    {
  "mcpServers": {
    "argocd-mcp": {
      "command": "/opt/homebrew/bin/npx",
      "args": ["argocd-mcp@latest", "stdio"],
      "env": {
        "ARGOCD_BASE_URL": "https://localhost:8080",
        "ARGOCD_API_TOKEN": "eyJhbGciOiJIUzI1NiIs..."
      }
    }
  }
}

    Anyone with read access to this file — or any process that scans config directories — can extract the token and gain full ArgoCD admin access.

    How ArgoCD MCP Authentication Works¶

    The ArgoCD MCP server is a Node.js process that Cursor spawns and communicates with over stdin/stdout (JSON-RPC). It reads ARGOCD_API_TOKEN from its environment, then uses it as a Bearer token against the ArgoCD REST API.

    The token itself is a JWT (JSON Web Token) — a base64url-encoded JSON payload signed with ArgoCD's server secret:

    header.payload.signature

    A decoded payload looks like:

    {
  "iss": "argocd",
  "sub": "admin:apiKey",
  "iat": 1780562370,
  "jti": "01ded6ae-ad7f-4d76-b7e7-d1c8430aca9b"
}

    The key insight: the MCP server only needs the token as an environment variable at startup. This means we can inject it dynamically rather than storing it in a file.

    Solution 1 — macOS Keychain (Recommended)¶

    The most secure approach for local development on macOS. The token is encrypted at rest and protected by your login password or Touch ID.

    Store the token¶

    security add-generic-password \
  -a "argocd-mcp" \
  -s "argocd-api-token" \
  -w "eyJhbGciOiJIUzI1NiIs..." \
  -T ""

    Create a wrapper script¶

    mkdir -p ~/.local/bin
cat > ~/.local/bin/argocd-mcp-start.sh << 'EOF'
#!/bin/bash
export ARGOCD_BASE_URL="https://localhost:8080"
export ARGOCD_API_TOKEN=$(security find-generic-password -a "argocd-mcp" -s "argocd-api-token" -w)
export NODE_TLS_REJECT_UNAUTHORIZED=0
exec /opt/homebrew/bin/npx argocd-mcp@latest stdio
EOF
chmod 700 ~/.local/bin/argocd-mcp-start.sh

    Update mcp.json¶

    {
  "mcpServers": {
    "argocd-mcp": {
      "command": "/Users/<you>/.local/bin/argocd-mcp-start.sh",
      "args": [],
      "env": {
        "PATH": "/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin"
      }
    }
  }
}

    Why this works with Cursor

    GUI apps on macOS don't inherit shell environment variables. A wrapper script sidesteps this by resolving the token at process spawn time — before the MCP server starts reading stdin.

    Rotate the token¶

    # Generate a new token
argocd account generate-token --account admin > /dev/null

# Update the keychain entry
security delete-generic-password -a "argocd-mcp" -s "argocd-api-token"
security add-generic-password -a "argocd-mcp" -s "argocd-api-token" -w "$(argocd account generate-token --account admin)"

    Solution 2 — .env File with Restricted Permissions¶

    Simpler but less secure than the keychain approach. Suitable when keychain access is impractical.

    Create a secured env file¶

    mkdir -p ~/.config/argocd-mcp
cat > ~/.config/argocd-mcp/.env << 'EOF'
ARGOCD_API_TOKEN=eyJhbGciOiJIUzI1NiIs...
EOF
chmod 600 ~/.config/argocd-mcp/.env

    Create the wrapper script¶

    cat > ~/.local/bin/argocd-mcp-start.sh << 'EOF'
#!/bin/bash
set -a
source ~/.config/argocd-mcp/.env
set +a
export ARGOCD_BASE_URL="https://localhost:8080"
export NODE_TLS_REJECT_UNAUTHORIZED=0
exec /opt/homebrew/bin/npx argocd-mcp@latest stdio
EOF
chmod 700 ~/.local/bin/argocd-mcp-start.sh

    Warning

    Add ~/.config/argocd-mcp/.env to your global gitignore (~/.gitignore_global) to prevent accidental commits.

    Solution 3 — 1Password / Bitwarden CLI¶

    If you already use a password manager with CLI support:

    #!/bin/bash
export ARGOCD_BASE_URL="https://localhost:8080"
export ARGOCD_API_TOKEN=$(op read "op://DevVault/ArgoCD MCP/token")
export NODE_TLS_REJECT_UNAUTHORIZED=0
exec /opt/homebrew/bin/npx argocd-mcp@latest stdio

    #!/bin/bash
export ARGOCD_BASE_URL="https://localhost:8080"
export ARGOCD_API_TOKEN=$(bw get password "argocd-api-token")
export NODE_TLS_REJECT_UNAUTHORIZED=0
exec /opt/homebrew/bin/npx argocd-mcp@latest stdio

    Note

    Both CLIs may prompt for biometric or master password unlock on first access per session.

    Solution 4 — Short-Lived Tokens (Most Secure)¶

    Generate a token that auto-expires each time the MCP server starts:

    #!/bin/bash
export ARGOCD_BASE_URL="https://localhost:8080"
export NODE_TLS_REJECT_UNAUTHORIZED=0

# Generate a token valid for 24 hours
export ARGOCD_API_TOKEN=$(argocd account generate-token \
  --account admin \
  --expires-in 24h \
  --server localhost:8080 \
  --insecure 2>/dev/null)

exec /opt/homebrew/bin/npx argocd-mcp@latest stdio

    Tip

    This requires the argocd CLI to have a valid session (via argocd login). The generated token expires automatically — even if leaked, the blast radius is limited.

    Comparison¶

    Approach Security Complexity GUI Launch Token Rotation
    macOS Keychain High Medium Yes Manual
    .env file (600) Medium Low Yes Manual
    1Password / Bitwarden High Medium Yes Manual
    Short-lived tokens Highest Medium Yes Automatic
    Plaintext in mcp.json None None Yes Manual

    Additional Hardening¶

    Restrict ArgoCD RBAC¶

    Instead of using the admin account, create a dedicated service account with minimal permissions:

    # In argocd-cm ConfigMap
accounts.cursor-mcp: apiKey
accounts.cursor-mcp.enabled: "true"

# In argocd-rbac-cm ConfigMap
policy.csv: |
  p, role:mcp-readonly, applications, get, */*, allow
  p, role:mcp-readonly, applications, list, */*, allow
  p, role:mcp-readonly, clusters, list, *, allow
  g, cursor-mcp, role:mcp-readonly

    Set token expiry at generation time¶

    argocd account generate-token --account cursor-mcp --expires-in 720h

    Audit token usage¶

    Check ArgoCD server logs for API calls made with the MCP token:

    kubectl logs -n argocd deployment/argocd-server | grep "cursor-mcp"

    Summary¶

    Never store long-lived ArgoCD tokens as plaintext in config files. Use a wrapper script to inject the token at runtime from a secure store — macOS Keychain for local dev, or a password manager CLI for cross-platform setups. For production-adjacent environments, prefer short-lived tokens with restricted RBAC.

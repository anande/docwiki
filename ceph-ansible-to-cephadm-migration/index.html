    Ceph-Ansible to Cephadm Migration Lab¶

    This document covers setting up a bare-minimum VM-based Ceph lab using ceph-ansible, followed by a migration plan to cephadm/cephadm-ansible. The goal is to simulate a real-world migration path in a resource-constrained lab environment.

    Why Migrate?

    ceph-ansible has been deprecated since Ceph Pacific. cephadm is the officially supported deployment and orchestration tool from Ceph Quincy onwards. Planning and testing the migration in a lab is critical before touching production clusters.

    Part 1 — Ceph-Ansible Lab Setup¶

    Lab Topology & Bare Minimum Specs¶

    A minimal 3-node Ceph cluster plus 1 admin/deploy node. All VMs can run on a single hypervisor (KVM/libvirt, VirtualBox, or Proxmox).

    Role Hostname vCPU RAM OS Disk OSD Disk(s) IP (example)
    Admin/Deploy ceph-admin 2 2 GB 20 GB — 192.168.56.10
    Mon + OSD ceph-node1 2 3 GB 20 GB 1 × 10 GB 192.168.56.11
    Mon + OSD ceph-node2 2 3 GB 20 GB 1 × 10 GB 192.168.56.12
    Mon + OSD ceph-node3 2 3 GB 20 GB 1 × 10 GB 192.168.56.13

    Total Resources

    ~8 vCPUs, ~11 GB RAM, ~100 GB disk. This fits comfortably on a 16 GB laptop or a small cloud instance.

    OSD Disks

    Each OSD node needs a separate raw/unformatted virtual disk (not a partition on the OS disk). In libvirt/VirtualBox, add a second .qcow2 or .vdi disk to each node.

    Base OS Preparation (All Nodes)¶

    Use Ubuntu 22.04 LTS (Jammy) or CentOS Stream 9. The examples below use Ubuntu.

    # Set hostnames (run on each respective node)
sudo hostnamectl set-hostname ceph-admin   # on admin
sudo hostnamectl set-hostname ceph-node1   # on node1
sudo hostnamectl set-hostname ceph-node2   # on node2
sudo hostnamectl set-hostname ceph-node3   # on node3

    Add entries to /etc/hosts on all nodes:

    /etc/hosts
    192.168.56.10  ceph-admin
192.168.56.11  ceph-node1
192.168.56.12  ceph-node2
192.168.56.13  ceph-node3

    # Update and install prerequisites (all nodes)
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-pip python3-venv chrony lvm2

    SSH Key Setup (Admin Node)¶

    # On ceph-admin
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519

# Copy to all nodes (including admin itself)
for host in ceph-admin ceph-node1 ceph-node2 ceph-node3; do
    ssh-copy-id -i ~/.ssh/id_ed25519.pub ubuntu@${host}
done

    NTP Sync (All Nodes)¶

    Ceph is sensitive to clock skew. Ensure chrony is running:

    sudo systemctl enable --now chrony
chronyc tracking

    Install ceph-ansible (Admin Node)¶

    Ceph Release

    This lab uses Ceph Quincy (17.2.x) as the last release with ceph-ansible support. For Pacific (16.2.x), adjust the branch accordingly.

    # On ceph-admin
sudo apt install -y git ansible

git clone https://github.com/ceph/ceph-ansible.git -b stable-7.0
cd ceph-ansible

pip3 install -r requirements.txt

    Configure ceph-ansible¶

    Ansible Inventory¶

    ceph-ansible/inventory/hosts
    [mons]
ceph-node1
ceph-node2
ceph-node3

[osds]
ceph-node1
ceph-node2
ceph-node3

[mgrs]
ceph-node1

[mdss]

[rgws]

[clients]
ceph-admin

    Group Variables¶

    ceph-ansible/group_vars/all.yml
    ---
ceph_origin: repository
ceph_repository: community
ceph_stable_release: quincy
ceph_repository_type: cdn

monitor_interface: enp0s8          # adjust to your VM network interface
public_network: "192.168.56.0/24"
cluster_network: "192.168.56.0/24" # same as public in lab

dashboard_enabled: true
dashboard_admin_user: admin
dashboard_admin_password: admin123  # lab only — never use in production

ceph_conf_overrides:
  global:
    osd_pool_default_size: 2       # 2 replicas for a 3-node lab
    osd_pool_default_min_size: 1
    mon_allow_pool_delete: true
    ceph-ansible/group_vars/osds.yml
    ---
osd_scenario: lvm
osd_objectstore: bluestore

lvm_volumes:
  - data: /dev/vdb    # the second virtual disk on each OSD node

    Finding the OSD Disk Device

    Run lsblk on each OSD node to confirm the device name. It's typically /dev/vdb or /dev/sdb depending on your hypervisor.

    Ansible Config¶

    ceph-ansible/ansible.cfg
    [defaults]
inventory = inventory/hosts
remote_user = ubuntu
host_key_checking = False
retry_files_enabled = False
log_path = ./ansible.log

[privilege_escalation]
become = True
become_method = sudo
become_user = root

    Deploy the Ceph Cluster¶

    cd ~/ceph-ansible

# Run the site playbook
ansible-playbook site.yml -i inventory/hosts

    Deployment Time

    First run takes ~15-25 minutes depending on download speeds. Subsequent runs are faster due to caching.

    Validate the Cluster¶

    SSH into any mon node and check:

    sudo ceph -s
sudo ceph osd tree
sudo ceph health detail
sudo ceph df
    Expected Healthy Output 
      cluster:
    id:     a1b2c3d4-e5f6-7890-abcd-ef1234567890
    health: HEALTH_OK

  services:
    mon: 3 daemons, quorum ceph-node1,ceph-node2,ceph-node3
    mgr: ceph-node1(active)
    osd: 3 osds: 3 up, 3 in

  data:
    pools:   1 pools, 1 pgs
    objects: 0 objects, 0 B
    usage:   3.0 GiB used, 27 GiB / 30 GiB avail
    pgs:     1 active+clean

    Create a test pool to confirm writes work:

    sudo ceph osd pool create testpool 32
sudo rados -p testpool bench 10 write --no-cleanup
sudo rados -p testpool bench 10 seq

    Part 2 — Migration to cephadm-ansible¶

    Migration Overview¶

    The migration follows the official Ceph documentation pattern:

    graph LR
    A[ceph-ansible cluster] --> B[Install cephadm on a mon]
    B --> C[Adopt existing daemons]
    C --> D[cephadm manages all daemons]
    D --> E[Remove ceph-ansible artifacts]

    Key Constraints

    • Migration must be done one daemon type at a time (mons first, then mgrs, then OSDs).
    • The cluster remains operational throughout — no downtime required.
    • Always back up /etc/ceph/ and monitor keyrings before starting.

    Pre-Migration Checklist¶

    • Cluster is HEALTH_OK (or only known warnings)
    • All OSDs are up and in
    • No recovery/backfill in progress
    • /etc/ceph/ceph.conf and all keyrings are backed up
    • NTP is synced on all nodes
    • Docker or Podman is installed on all nodes
    • Ceph version is at least Quincy 17.2.x
    # Verify cluster health
sudo ceph -s
sudo ceph osd tree

# Backup critical configs
sudo tar czf /root/ceph-backup-pre-migration.tar.gz \
    /etc/ceph/ \
    /var/lib/ceph/bootstrap-osd/ \
    /var/lib/ceph/bootstrap-mds/ \
    /var/lib/ceph/bootstrap-rgw/

    Install Container Runtime (All Nodes)¶

    cephadm runs Ceph daemons in containers. Install Podman (preferred) or Docker:

    # On all ceph nodes
sudo apt install -y podman
podman --version

    Install cephadm (Mon Node — ceph-node1)¶

    # On ceph-node1 (a mon node)
sudo apt install -y cephadm

# Verify
cephadm version

    Match Versions

    Ensure the cephadm version matches your running Ceph cluster version. For Quincy: 

    sudo cephadm install --release quincy

    Prepare cephadm to Adopt the Cluster¶

    # On ceph-node1
# Tell cephadm about the existing cluster
sudo cephadm adopt --style legacy --name mon.ceph-node1

# Verify the mon is now running in a container
sudo cephadm ls
    Expected Output from cephadm ls 
    [
    {
        "style": "cephadm:v1",
        "name": "mon.ceph-node1",
        "fsid": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
        "systemd_unit": "ceph-a1b2c3d4-mon@ceph-node1",
        "enabled": true,
        "state": "running"
    }
]

    Step-by-Step Daemon Adoption¶

    Step 1 — Adopt Monitors¶

    Adopt monitors one at a time. Verify quorum after each adoption.

    # On ceph-node1 (already adopted above)
# Now adopt remaining mons — run cephadm on each respective node

# On ceph-node2
sudo cephadm adopt --style legacy --name mon.ceph-node2

# On ceph-node3
sudo cephadm adopt --style legacy --name mon.ceph-node3

# Verify quorum
sudo ceph mon stat
sudo ceph -s

    Step 2 — Adopt Manager¶

    # On ceph-node1 (where mgr runs)
sudo cephadm adopt --style legacy --name mgr.ceph-node1

    Step 3 — Adopt OSDs¶

    Adopt each OSD individually. Check OSD status after each adoption.

    # Find OSD IDs on each node
sudo ceph osd tree

# On ceph-node1
sudo cephadm adopt --style legacy --name osd.0

# On ceph-node2
sudo cephadm adopt --style legacy --name osd.1

# On ceph-node3
sudo cephadm adopt --style legacy --name osd.2

# Verify all OSDs are up
sudo ceph osd tree

    OSD Adoption

    OSD adoption is the most sensitive step. If an OSD fails to start after adoption, check logs with: 

    sudo cephadm logs --name osd.<id>
journalctl -u ceph-<fsid>@osd.<id>.service

    Using cephadm-ansible for Remaining Operations¶

    Once all daemons are adopted, use cephadm-ansible for orchestrated management.

    # On ceph-admin
git clone https://github.com/ceph/cephadm-ansible.git
cd cephadm-ansible

    cephadm-ansible Inventory¶

    cephadm-ansible/inventory/hosts
    [admin]
ceph-node1

[clients]
ceph-admin

    Note

    cephadm-ansible only needs to know the admin node (where cephadm shell runs). cephadm itself manages the cluster topology via its orchestrator.

    Preflight Playbook¶

    ansible-playbook -i inventory/hosts cephadm-preflight.yml \
    -e "ceph_origin=repository" \
    -e "ceph_repository=community" \
    -e "ceph_stable_release=quincy"

    Post-Migration Cleanup¶

    After all daemons are adopted and running in containers:

    # Disable and remove legacy ceph packages (on all nodes)
sudo systemctl disable ceph.target
sudo apt remove -y ceph-mon ceph-osd ceph-mgr ceph-mds ceph-common || true

# Verify everything runs via cephadm
sudo cephadm ls
sudo ceph orch ps
sudo ceph orch ls

    Final Validation¶

    # Full cluster health
sudo ceph -s
sudo ceph health detail

# All daemons managed by cephadm
sudo ceph orch ps

# Test I/O on existing pool
sudo rados -p testpool bench 10 write --no-cleanup
sudo rados -p testpool bench 10 seq

# Dashboard should still be accessible
sudo ceph mgr services
    Expected Final State 
      cluster:
    id:     a1b2c3d4-e5f6-7890-abcd-ef1234567890
    health: HEALTH_OK

  services:
    mon: 3 daemons, quorum ceph-node1,ceph-node2,ceph-node3
    mgr: ceph-node1(active)
    osd: 3 osds: 3 up, 3 in

  data:
    pools:   2 pools, 33 pgs
    objects: 42 objects, 1.2 MiB
    usage:   3.1 GiB used, 26.9 GiB / 30 GiB avail
    pgs:     33 active+clean

    Tips & Troubleshooting¶

    Issue Resolution
    cephadm adopt fails with permission error Ensure passwordless sudo is configured for the user
    OSD won't start after adoption Check LVM is intact: sudo lvs, sudo vgs
    Mon quorum lost during adoption Adopt only one mon at a time, verify quorum between each
    Container image pull fails Pre-pull on all nodes: sudo podman pull quay.io/ceph/ceph:v17
    Clock skew warnings Verify chrony: chronyc tracking on all nodes
    Dashboard inaccessible after migration Re-enable: sudo ceph mgr module enable dashboard
